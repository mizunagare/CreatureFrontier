# P1 — 有限资源采集

当前实现范围：资源点库存与玩家/伙伴共用采集结算；不是完整制造、材料搬运或仓储系统。

## 规则

- `M` 瞄准 3 米内资源点，成功一次获得 1 材料。重复按键受该资源点共享的 0.8 秒冷却约束。
- 采集、采矿、制造站现在分别派遣伙伴寻找草丛、矿点、废料。制造站此阶段执行有限废料回收，不是凭空制造材料；玩家配方制作保持不变。
- 伙伴寻找工作站 8 米内匹配资源，实际寻路并在 2.2 米内、有视线时累计工作。专长影响速度，饥饿减速与疲劳休息沿用已有规则。
- 到达前不产出；无资源时等待并重试。寻路超过 8 秒放弃当前目标，2 秒后重试，失败资源暂避 5 秒，不使用瞬移。
- 默认每份需要 3 工作单位。玩家与所有伙伴争用同一资源库存、共享冷却；仅材料入包成功后扣库存。失败不扣资源、不发经验/生产任务进度。
- 背包满保留就绪工作，不消耗资源；指令中断、改派或读档清除未结算进度，已结算材料不会因重试再次结算。
- 草丛容量 24，耗尽后经过 180 秒**未暂停的游戏时间**恢复整批；矿点容量 30、废料容量 18，耗尽后不刷新。恢复只补节点库存，不直接发放材料或经验。
- 当前基地附近与外围各有三类节点，共六处。外围节点鼓励外出手采或建立合适工作站，不自动跨地图工作。

## 数据与持久化

`UResourceDefinition` Data Asset 保存显示名、工作类型、容量、工作时长、共享冷却、恢复时长与颜色。
三个资产位于 `Content/Resources`，可用 `Content/Python/create_resource_definitions.py` 幂等生成。
初始位置与稳定 GUID 统一在 `SpawnStarterResources` 中定义，尚未迁移为地图作者工具或分区资源表。

格式 17 保存每个资源点的 GUID、定义、位置、剩余量、采集冷却与恢复剩余时间，同时保存背包/伙伴/世界。
读取格式 1–16 时，旧档没有资源历史，因此初始化一次默认资源布局；保留原有背包与伙伴，不凭空扣除历史材料。
迁移后重新保存为 17，随后加载精确恢复资源状态；空库存不能因重新进程、重复加载或旧节点合并而被补满。
重新加载旧快照会连同背包一起回退，属于世界快照回滚，不是在线经济或防作弊账本。

资源先在临时事务中完整校验/生成，所有世界数据恢复成功后才替换旧节点。
重复 ID、非法库存/变换/时间、缺失定义或后续伙伴恢复失败会销毁临时节点并保留当前世界。
离线不计时，新程序保存的 17 不能交给旧程序读取。请保留旧构建和原始存档备份。

## 当前边界

- 三类节点暂统一产出已有的 `Material`，没有木材/石料/金属独立物品、工具耐久或稀有掉落。
- 伙伴采集产物直接入玩家背包；尚无材料携带、材料仓库或从资源点送货的路线。
- 食物农圃/搬运/食槽沿用原系统；种子、浇水、种植阶段不在本轮实现范围。
- 节点是可瞄准的原生几何占位，不阻挡角色或导航，非完整树木/矿脉美术与物理破坏。
- 近距世界文字标签偏大，可能与常驻 HUD 重叠；本轮图形检查确认耗尽模型与恢复倒计时可见，不代表最终交互 UI 品质。
- 六处固定预算与恢复参数仅为灰盒值，未进行完整游戏经济/长时性能平衡。
- 专项覆盖固定绕墙路径与两个工人竞争；任意建筑封堵、多工人拥挤、长时恢复循环及大地图分区尚未充分验证。

## 本地复验入口

`-CFResourceTest`：手采射线、范围/视线/存活门槛、共享冷却、竞争末份库存、满包守恒、中断清零、耗尽等待、恢复、重复读档、工作意图、坏档回滚、旧档迁移和真实绕墙采集。
`-CFResourceTest -CFResourcePreview`：通过后生成 `Saved/ResourcePreview.png`；图形模式不能同时使用 `-nullrhi`。
跨进程的 `-CFSaveWrite` / `-CFSaveRead` 同时检查耗尽资源及两个剩余计时，不以同进程往返代替退出重开。
完整本地回归使用 `Scripts/Test-Packaged.ps1`，不创建自动 CI。
