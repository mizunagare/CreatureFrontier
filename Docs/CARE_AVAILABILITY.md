# 陪伴操作可用性（开发中）

## 缺口与方案

自然救助实战中，活伙伴对象卡总是展示Y/F6，即使实际操作会因距离、战斗、冷却、体力/饱食或附近野生生物而拒绝。玩家需要在按键前理解当前状态，不能只依赖按键后的错误反馈。

从原InteractCompanion拆出只读CanInteractCompanion查询，返回可用性和原拒绝原因；执行仍在按键时重新查询，HUD调用同一函数，不维护第二套门槛。原检查顺序、提示、2.5米、600厘米安全半径、30秒冷却、20体力/饱食、归属/视线/暂停门槛均保留。不增加存档字段，不改关系数值或消耗。查询不改世界、反馈、亲密度或冷却，只填写调用者的原因输出。

HUD在不可用时显示原因，安静陪伴可用而玩耍不可用时显示对应区别；J/P/F/T另列，命名/回忆增加“安全空闲时”限定。这里只统一抚摸与玩耍，不声称命名、喂养、回忆和治疗都共用相同门槛。拒绝原因沿用原先的首个失败条件，例如距离过远优先于战斗，不能将提示视为所有阻挡条件的完整列表。
