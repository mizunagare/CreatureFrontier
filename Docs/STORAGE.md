# 基地储物箱（格式 21）

后续格式 22 已加入材料/水晶的伙伴实际入箱交付，见 `Docs/CARGO_DELIVERY.md`。本页保存手动仓储规则与格式 21 的历史验收；六类手动存取不表示六类都有自动生产物流。
格式 23 支持九类物品，仓储面板扩展行数，新增原料与加工规则见 `Docs/MATERIALS.md`；本页历史哈希不是格式 23 的回归证据。

## 可玩目标与操作

将探索所得带回基地，存入自己建造的实际容器，给后续伙伴物流提供明确的交付点。此版完成玩家仓储，不把直接入包的采集或现有食物运输改称通用材料物流。

- `B` 建造、`8` 房屋分类、`V` 选择 **Storage crate**。消耗 6 材料，依附已有地板；地板另消耗 8 材料。箱子使用同一模块 GUID、预览、真实碰撞、导航和支撑系统。
- 基地原有 12 米建造范围、单层地板、100 厘米家具网格和总计 128 模块上限不变。箱子需完整位于地板内部，不能拆掉支撑地板。
- 瞄准箱子按 `E`，需活着、未暂停、3 米内且视线通畅。未命中箱子时仍沿用资源/工作站派工；命中箱子但访问失败不会误发工作令。
- 面板中 `↑/↓` 选物品，`Enter` 存 1，`Backspace` 取 1，`→` 存选中物品整堆，`←` 取整堆，`E` 关闭。操作前再次验证距离、视线、存活、暂停和有效目标，不靠打开时的一次检查授权后续远程存取。
- 六类现有物品均可存取，每类上限 999，不是总重量/格子背包。整堆操作全成或全不成，不自动部分转移。容量不足需手动逐份腾挪。
- 世界仍然运行。离开范围、视线失效、打开其他面板或建造后失去访问；暂停、死亡和成功读档关闭当前箱子交互。
- 非空箱子拒绝拆除；取空后才能按 `X` 拆除，按实际支付材料返还一半。退款也必须完整入包，否则不拆。

当前箱体为三块简单几何组成的灰盒，面板沿用临时 Canvas 文字，不是正式美术、动画或 UI 品质。

## 守恒与职责

`UInventoryComponent::TransferTo` 是权威游戏线程上的双容器事务：先复制并验证双方库存与所有物品数量，检查来源充足、目标容量、不同容器、同一世界及双方 Actor 存活，再提交两份结果。失败不先从一方扣除，也没有中途回调或第二个可失败结算。

新物品不会因为存取而产生，研究/采样知识与经验也不会因为水晶存取而授予。泛用背包组件默认空，玩家新手物资由玩家 BeginPlay 初始化，读档不重复运行该初始化；箱子和预览不会继承玩家的新手包。

`UStorageInteractionComponent` 负责瞄准、访问门槛、面板状态和请求，HUD 负责显示；房屋模块只承载容器、物理几何和原稳定标识，存档仍走房屋分阶段恢复事务。没有另建第二套设施/支撑/拆除系统。

## 存档与恢复

格式 21 在房屋记录增加 `StoredItems`。保存箱子的 GUID、支撑地板、物品与实际支付成本；加载阶段先验证所有记录并在不可碰撞、不可访问的 staged Actor 中恢复物品，全部世界数据合法后才替换旧世界。

未知物品、负数/超 999、非箱模块携带库存、未知支撑、重复模块 GUID、与快照中设施的实体重叠等均拒绝。后续生物记录无效也必须回滚已暂存箱子，不删除旧箱或更改双方库存。

读取 1–20 沿用原迁移链，不生成新箱子或物品；18–20 的旧房屋记录忽略未来库存字段，但不能伪装存储新 Storage 类型。1–17 沿原规则无房屋模块。反复读档不额外发库存或退款。新档不能交给旧版程序，升级前保留旧档备份。

## 验收入口与边界

`CFStorageTest` / `CFStorageWrite` / `CFStorageRead` 三项包含实际建造付款、真实 E 射线打开、面板路由选六类物品逐份存取与整堆往返、混合批次容量失败原子性、自转移/非法数量拒绝、远距/隔墙/暂停/预览/暂存拒绝、非空与地板拆除拒绝、取空退款、两次加载精确 GUID/库存、九类坏档保持旧世界、20 迁移不发物品、实际伤害倒下后拒绝存取，以及跨进程恢复。

初始库存和迁移/容量故障由测试夹具明确设置，不以这些夹具发物品证明正式采集；正常资源采集/探索和旧食物运输继续由原回归覆盖。未单独覆盖任意混合建筑布局、多个箱子的长时压力、资源点到箱子的自动采集/运输、箱间调拨、鼠标拖放、重量与分类筛选。任意外部销毁 Actor 仍可能丢其剩余库存，正式拆除入口通过非空拒绝避免这一问题。
