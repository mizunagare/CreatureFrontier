### 本轮工作与验收门槛

目标仅为收尾跟随稳定性，不扩展新物种或新孤立面板。
涉及 `CreatureCharacter`、`CompanionFormation`、`FormationScenario`、本地测试脚本与相关文档。
风险为交叉寻路、角色碰撞、停靠时过度避让、工作/战斗/照料回归和读档重建。
验收要求：真实绕障与转向、迎面玩家碰撞回避、六槽/状态排除、停稳后间距、数据守恒、读档；
完整 28 类本地打包回归，跟随场景单独重复 3 次，并做 30/60/120 帧率上限的图形复测。
失败日志保留在本机 Saved，修复后使用新日志重跑；不得将旧构建的一次成功当作当前修正版验收。

### 下一阶段：先闭合资源与家园循环

1. **P0 跟随稳定性**：本轮按下述范围验收完成；如出现新复现先修复，不把三宠场景通过扩大解释为任意规模稳定。
2. **P1 有限资源点与采集**：玩家和伙伴使用同一资源来源；定义库存、产出、耗尽、恢复与稳定标识；验证中断/失败/读档不重复结算。先替换现有凭空产材料占位。
3. **P2 模块化家园最小闭环**：地板、墙、门洞和屋顶形成可进入的房间，复用/扩展现有吸附、支撑、碰撞、拆除、导航与快照机制；门窗、楼梯、栅栏和装饰逐步扩展。
4. **P3 第二条探索回路**：有差异的资源与危险、伙伴协作和建筑/配方解锁，让一次外出、返家与下一次外出具有联系，不只扩大地图。
5. **P4 伙伴个体与品质**：根据实际内容引入个体 ID、命名、偏好和关系事件；完善正式角色/动画/声音/UI，并记录性能预算。

各阶段交付均包含独立 Windows 构建、明确玩法目标、退出重开/旧档恢复与本地回归证据。项目禁止自动 CI；当前本地与已检查的远端均未发现 `.github/workflows`。
