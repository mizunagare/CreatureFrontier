# 普攻剩余冷却存档修复

## 缺口与兼容策略

前置诊断见 `COMBAT_OUTCOME_TRACE.md`：实际正值普攻冷却读回为零，造成提前出手。修复只保存、验证并恢复生物现有的 `AttackCooldown`，不改变攻击间隔、伤害、射程、碰撞或技能规则。

总格式保持38，生物记录增加独立 `CombatCooldownVersion` 和 `MeleeCooldown` 属性。带名称的旧记录缺字段时修订为0；仅允许冷却为0，读取后双方各等待自己的原攻击间隔一次，避免把未知剩余值当作立即就绪。新写记录修订1，精确保留包括0在内的有限非负冷却，上限为该定义的原攻击间隔。未知修订、负值、超上限、非数、无穷及旧修订携带非零值均拒绝。

该策略支持旧档进入新程序，不保证不理解新字段的旧程序往返后还能保留新语义。不要使用旧构建重存新档来验证本修复。恢复进行中的技能蓄力、瞬时路径和玩家自身攻击计时不在本项范围。

## 专项验收

`Scripts/Test-MeleeCooldown.ps1` 使用真实旧接敌中途档，保护四个专用测试槽并核对输入和程序指纹。边界夹具只用于存档单元验收，不用于伪造普通战斗成果。检查旧档六只生物迁移、新记录0／上限／半间隔及往返；六类坏记录置于最后一项，检查先前暂存对象回滚后玩家位置／生命／库存、生物对象集合／位置／冷却保持。

真实 `-Flank` 链另外要求保存时至少有一个自然产生的正值冷却，并在新进程恢复后、首次世界更新前逐项精确比较。技能可能先于普攻命中，因此测试有界等待真实普攻，不直接设置冷却、不重复下令，也不取消正值门槛。
