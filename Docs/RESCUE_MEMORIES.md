# 脱险归家共同经历（设计审计，尚未实现）

## 可玩目标

伙伴在共同冒险中真正被敌人击倒，玩家用已有药品救助，再带它走回基地。安全相聚时按F7，可选择安静陪伴或庆祝归来，伙伴以不同动作回应，并保存这次共同经历。不是治疗任意伤口便发放奖励，不要求为了事件杀死敌人；允许撤离。不给物品、经验、亲密度、免费回血或属性加成。

本页是基于当前代码的实现约束，不代表功能已交付。稳定包仍为Windows-Care-Route，格式28。

## 已检查的实际接缝

- `CreatureCharacter.cpp::TakeDamage` 有真正的伤害事务、攻击者、致死转折及攻击者EncounterId，可作为经历来源。当前死后Tick会提前返回；不能在该返回之后才记录倒地。
- `CFPlayerCharacter.cpp::HealCompanion` 先射线选中自己的伙伴、检查满血、消耗一药，再恢复40生命；不区分受伤与倒地，也没有经历来源记录。新记录必须在原消耗成功后，仅针对治疗前确实倒地且有来源的个体，不改治疗门槛与消耗。
- `CompanionMemoryComponent` 目前只有CrystalJourney四状态，窗口正文、待分享判断及提交均绑定水晶。F7已集中在RecallAimedJourney，不应再绑定一套输入或另建抢焦点的窗口组件。
- `FrontierSaveGame.h` 用原始uint8保存CrystalJourney，载入在替换世界前校验；根默认21，实际写28。未知枚举不得静默退回None。旧格式迁移也不能根据研究、地图或残血猜测经历。
- 现有回忆专项用瞬时放置夹具检查事务与窗口，不证明真实归家。救助自然链已有真实移动、独立进程读档和GUID检查，应扩展它，而不是将位置夹具冒充新内容验收。
- AWildEncounter有稳定EncounterId与展示名，但没有冒险回忆资格配置。区域范围不应复制生成脚本里的坐标；来源应由栖息地配置和真实攻击者身份决定，不能在HUD/治疗/存档各写一份洞窟判断。

## 拟定状态与职责

复用Memory组件，新增独立救助经历状态，保留CrystalJourney字节及其含义。拟定流程：无经历 → 有来源的倒地 → 已救助待归家 → 安全归家待分享 → 安静回应/庆祝回应。状态与来源必须跟随生物GUID保存，不依赖Actor名字、数组索引或当前编队次序。

倒地来源只接受权威实际正伤害导致的存活到倒地转折：自己的驯服伙伴、主人存活且在场、攻击者来自配置允许的野生栖息地。普通直接改HP、环境夹具、友伤、他人伙伴、野外远程旁观和治疗失败不产生新经历。第一版只配置余烬洞窟，不将其宣传为全世界通用剧情。实际距离和视线条件须在实现时集中定义并以边界测试锁定，不在多处散布魔数。

救助记录只在原药品事务成功后推进；重复治疗不重置已完成记忆。返家记录由正常运行中的伙伴实际到达、安全、存活且主人同行条件推进，不在Open里凭空创建。途中的暂停/再次倒地保留已发生事实，但不能在倒地或战斗中分享。离线不累计行走或自动完成；读档恢复的是快照时间线，不保证撤销读档后仍永久记住未来。

F7由同一组件选择待分享经历。窗口打开时锁定事件类型，提交只更新该事件；不能因另一个事件也Pending而写错水晶状态。两条都Pending时需要确定顺序与可见提示，首版可固定水晶优先、完成后再按F7分享脱险，不引入通用任务图或无需求的剧情框架。HUD/队伍应同时保留两条摘要，不能新摘要覆盖旧记忆；需重新评估小窗口预算。

保留现有Open/Commit/Close及输入恢复边界。取消不消耗事件；暂停内只允许窗口自身确认，照料仍拒绝。读档成功、主人倒下、目标销毁需关闭；坏档拒绝必须保留旧世界/窗口/暂停状态。外部目标倒下提交拒绝，是否自动关窗应明确实现与验证，不能只凭已有Close函数宣称覆盖。

## 持久化方案与风险

预计格式29，根默认21继续冻结。救助状态用原始字节，来源用稳定EncounterId，校验状态范围、来源资格、拥有/驯服关系及空状态与来源一致性；共享进度不能只校验一个bool。存活/倒地应按状态允许再次受伤，不能错误拒绝“已救助后又倒地”的真实快照。来源配置缺失或矛盾须在替换世界前明确拒绝，不吞字段。

1–28一律清空新增经历，不凭旧档倒地状态补历史，原水晶、昵称、偏好、携带物、工作意图、数值和有限资源按既有迁移保留。所有等于28的测试应区分“新写档当前版本”与“真实历史28样本”，不能全局替换数字来制造兼容通过。现有16份真实28档保留，另保存新增每个中间状态的29真实样本。
