# 二层农圃与跨楼层任务恢复

## 目标与实现边界

复用木楼梯的两层组合，验证同一伙伴接到二层农圃工作后，能够从楼下实际上楼生产；玩家实际上楼取粮，再带原伙伴归队下楼。已有农业接近点按设施高度限制导航投影，合法放置、工作状态机和保存流程可直接复用，本项没有另建生产系统，也没有修改生产效率、工作距离、导航跨阶能力或正常开局资源。

本次新增的是显式 `-CFStairsWork` 整合场景及脚本入口。仍为单伙伴、东向楼梯、12模块两层组合的固定建造观察站位；初始化沿用楼梯专项对无关野生AI的隔离，受测自有伙伴保持正常Tick和碰撞。不是普通玩家自然开局建成完整两层房屋；其他朝向、多伙伴同梯、长期循环和任意多层未在本项验收。

## 玩家操作与预期结果

1. 按 `Docs/STAIRS.md` 的原流程建好相邻平台、承重墙、二层楼板和木楼梯，保持踏步、出入口及头顶空间畅通。
2. 在二层平台上按B进入建造，使用8切到设施，V选择农圃，瞄准楼板确认绿色预览后放置；农圃消耗18材料，不能侵占楼梯通行区域。
3. 背包持有种子时，靠近并瞄准农圃按F2存入一份。需要种子时在C背包中选择“准备种子”配方，实际按其材料要求制作。背包里的种子不会自动补进农圃。
4. 选择伙伴，从楼下在8米内瞄准可见的二层农圃按E派工，检查反馈确实指向目标设施。按F5保存、F9恢复后，应保留原农圃库存、原伙伴及工作关系；伙伴按正常导航上楼，而不是瞬移到设施。
5. 伙伴正常耕作产粮后，玩家实际上楼靠近并瞄准农圃按O取出；按F取消原工作并跟随，再经楼梯下楼。没有追加种子时不再生产，不应自动消耗玩家背包种子。

上述为普通操作说明；自动专项使用引擎注册动作／按键委托和持续移动输入，存读直接调用现有 `SaveProgress`／`LoadProgress`，不等同于已完成人工鼠标、F5／F9硬件操作或完整自然风险验收。

## 整合专项与资源账本

`Scripts/Test-Stairs.ps1 -Work` 复用原12模块预览建造。明确夹具为200材料、2份种子及一只直接驯服的测试苔跳兽：建筑花88、农圃花18，余94材料；F2实际存1种，背包余1。农圃位于 `(100,-700,325)`，尺度 `(2,1,.7)`，二层楼板表面290厘米；初始伙伴位于 `(-1100,-800,40)`、玩家位于 `(820,-700,40)`。

正常瞄准E派工后，在伙伴仍在楼下、农圃储种1／食物0／未种植时保存 `UpperFarmAutomation`；原12模块、农圃GUID、伙伴GUID、库存和工作关系须一致。同进程正常读取后让伙伴自然上楼，跨过中间踏步高度并真正进入平台，再实际生产1份粮食、经验增加1。玩家从楼外围走到楼梯上楼O取粮，F归队后双方实际下楼，最终再次保存／读取 `UpperFarmDoneAutomation`。全过程保持双方碰撞、伙伴Tick、真实移动模式和逐帧位移上限，不在行走开始后设置双方位置。

最终为12模块／1农圃、94材料／1背包种子／1食物，农圃种子和食物均0、作物进度0，原伙伴跟随且无工作目标／野外采集／货运订单。持有那份背包种子而不自动续种，也在实际走近取粮过程中核对；没有赠送额外产物或反复获取经验。

独立 `-Work -Mode Read -ReadInputPath <独立副本>` 直接恢复楼下派工档，不重建、不播种、不重下E，再走完同一生产／取粮／归队链。脚本检查必要阶段标记及两份GUID一致，保存工作态和最终态副本、SHA-256和CSV；读取源及工作态槽哈希须不变。格式仍为34，没有新增存档字段。

脚本保护 `UpperFarmAutomation`、`UpperFarmDoneAutomation`，并继续保护可能被旧程序写入的 `StairsAutomation`、`StairsInvalid`。不写常规玩家进度；原测试槽恢复，原不存在的新槽只清理本次生成文件。`-Work` 不支持旧档模式或原楼梯预览，两个非法组合已实际在启动前拒绝。
